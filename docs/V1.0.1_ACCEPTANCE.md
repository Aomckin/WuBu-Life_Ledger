# 物簿 v1.0.1 验收

2026-11-15 在独立临时服务与 SQLite 数据库上验收。

| 场景 | 验收结果 |
| --- | --- |
| A 每周同步 | 微信 CSV/XLSX 与支付宝 CSV 自动识别、自动预览。修改账户映射后自动更新预览，提交后重载页面并再次导入，已确认映射恢复。同一文件重导没有新增流水。退款关联原支出，坏行与未知账户保留待确认。银行账单选择实际模板和账户。 |
| B 说明编辑 | 便利店消费仅提交分类字段。商家、金额与账户余额保持原值。 |
| C 资金歧义 | 缺账户时仅选择账户。相同金额的多笔候选按时间、商家、金额展示，可直接选定其中一笔。退款从实际可退支出中选择。 |
| D 快捷记账 | “晚饭 16 元”使用可靠默认账户入账。账户留空时保存为待匹配证据，实际账户和历史未归属账户的余额均保持不变。 |
| E 购入和关联 | 输入“无糖可乐”和“2 瓶”后库存增加两瓶。再次只填数量时沿用“瓶”。资金关联可按金额、日期、商家或描述搜索并选账。 |
| F 可靠性 | Go 测试和 vet、前端静态检查、三套 Edge 浏览器验收及真实朝汐 SDK 的只读导入测试通过。资金校正覆盖账户、金额、方向、幂等、退款上限、检查点、原始证据与外部交易号去重。 |

从现有的真实 Schema 16 账本副本建立 SQLite 备份，再用另一份副本启动 v1.0.1。升级至 Schema 17 后重启，逐行比对 36 张原表共 725 行，结果一致。其中有 125 笔资金流水、24 条库存事件、105 条原始财务证据、103 条证据关联、18 条领域关联及 36 条幂等记录。升级副本及从备份恢复的 Schema 16 库均通过 `integrity_check` 和 `foreign_key_check`。

开发验收期间使用临时服务，朝汐源码与环境未写入。资金校正支持普通支出、收入和退款，需要有效目标账户。涉及居住债权、计划结算或与新方向冲突的关联时，先处理对应关系。银行模板仍由用户选择，账户归属以账单和明确配置为准。

## 本机部署

2026-11-15 经用户授权，正式实例切换至 v1.0.1，监听 `127.0.0.1:8026`。停服后备份原 Schema 16 数据库及 RC2 程序，备份位于 `.runtime/v101-release-20261115151351-8b3412/backup`。正式库升级为 Schema 17 后通过完整性、外键及 36 张原表共 725 行的逐行校验。在正式站点用 Edge 检查了首页、快捷支出、独立购入、每周同步和已入账流水。
