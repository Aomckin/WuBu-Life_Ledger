# 物簿 v0.3 开发任务书

> 项目：**物簿 Wubu / Life Ledger**
>
> 版本：**v0.3**
>
> 版本主题：**Living Runway**
>
> 一句话目标：
>
> **从“记录我现在有多少钱和什么东西”，升级为“告诉我接下来还能怎么生活”。**

---

# 0. 版本背景

v0.1 解决：

```text
现实发生一次
→ 钱和物被记录下来
```

v0.2 解决：

```text
钱在哪里
物在哪里
它们经历了什么
```

v0.3 开始解决：

```text
未来有哪些钱已经不能随便花？
现在真正安全可花多少？
当前生活成本是多少？
深圳落地到底花了多少钱？
现有物资还能撑多久？
```

本版本不是继续扩展专业财务功能。

目标是：

> **建立个人独立生活的运行状态层。**

---

# 4. 核心概念：Balance ≠ Safe-to-Spend

现有账户余额只能回答：

```text
“现在账户里有多少钱？”
```

不能回答：

```text
“其中多少真的可以随便花？”
```

例如：

```text
银行卡余额       ¥6000

未来房租        -¥2980
手机 / 水电等    -¥300
安全缓冲         -¥1000

真正可动         ¥1720
```

因此新增：

```text
Living Runway
```

# 6. Liquid Balance

如果 Account Classes 已存在：

```text
liquid_balance
```

只使用：

```text
STORAGE
```

中的自由资金。

不得将：

```text
会员余额
校园卡
门店储值
```

计入自由可用资金。

不得将：

```text
信用额度
```

视为现金。

---

# 7. Reserved Outflow

定义：

> 已知在未来指定时间窗口内必然或高度可能发生的支出。

例如：

```text
房租
水电
手机费
网络
固定订阅
服务器
保险
固定还款
```

这些钱：

```text
目前仍在账户里
```

但已经：

```text
事实上被未来预定
```

因此：

```text
safe_to_spend
=
liquid_balance
- reserved_outflow
- safety_buffer
```

---

# 8. Safety Buffer

允许用户配置：

```text
safety_buffer
```

支持两种形式：

```text
fixed amount
```

例如：

```text
¥1000
```

后续可扩展：

```text
N days baseline spending
```

v0.3 P0 只要求固定金额。

---

# 9. Safe Daily Spend

若已知下一笔主要收入日期：

```text
days_to_next_income
=
next_income_date - today
```

则：

```text
safe_daily_spend
=
safe_to_spend / days_to_next_income
```

如果：

```text
safe_to_spend < 0
```

返回：

```text
safe_daily_spend = 0
cashflow_warning = true
```

不得返回荒谬负日预算作为主要 UI。

---

# 10. 没有下一笔收入时

不能强制要求工资日。

如果没有 Expected Income：

使用用户配置：

```text
runway_horizon_days
```

默认建议：

```text
30 days
```

于是：

```text
safe_daily_spend
=
safe_to_spend / runway_horizon_days
```

返回结果必须注明：

```text
mode = FIXED_HORIZON
```

而不是伪装成真实“距离发薪还有 N 天”。

---

# 11. Future Cashflow

新增：

```text
PlannedCashflow
```

或符合现有代码风格的等价模型。

它描述：

> 尚未真实发生，但已知未来可能发生的钱流。

它不是：

```text
MoneyTransaction
```

---

# 12. 关键原则

绝对禁止：

```text
未来房租
↓
提前写入 MoneyTransaction
```

因为：

> MoneyTransaction 是已经发生的现实资金事实。

Future Cashflow 必须与真实流水分离。

---

# 16. 未来现金流与实际流水关联

例如：

```text
11月房租
¥2980
```

当真正付款以后：

```text
PlannedCashflow
↓
MoneyTransaction(EXPENSE)
```

然后：

```text
status = COMPLETED
linked_transaction_id = xxx
```

下一周期按 recurrence 生成或推进。

---

# 17. 不允许重复计算

一项 PlannedCashflow 一旦：

```text
COMPLETED
```

不得继续进入：

```text
reserved_outflow
```

否则会出现：

```text
余额已经扣一次
Runway 又预留一次
```

双重扣除。

---

# 18. Expected Income

工资等未来收入也进入：

```text
PlannedCashflow(direction=INFLOW)
```

但 Runway 默认计算应保守。

建议：

```text
safe_to_spend
```

默认：

> 不提前把未来工资算进当前可花余额。

Expected Income 主要用于：

```text
确定 runway 终点
显示未来现金流
```

而不是：

```text
“反正18天后发工资，所以今天可以先把未来工资花了。”
```

# 20. Expense Nature

```text

```

```text
这笔钱在生活中是什么性质？
```

二者必须分开。

---

# 21. Expense Nature 枚举

第一版：

```text
DAILY
FIXED
SETUP
CAPITAL
EXCEPTIONAL
```

---

# 22. DAILY

正常日常消费：

```text
吃饭
饮料
交通
零食
普通生活用品
```

---

# 23. FIXED

周期性生活义务：

```text
房租
手机费
网络
固定订阅
```

---

# 24. SETUP

一次性生活建设 / 搬迁成本：

```text
中介费
搬家
床单
枕头
初次生活用品
首次家具采购
```

用于回答：

```text
“我落地深圳到底花了多少钱？”
```

---

# 25. CAPITAL

耐用品 / 长期使用物品购置：

```text
显示器
电脑
桌子
椅子
厨电
自行车
```

不代表严格会计意义上的 Capital Expenditure。

只是：

> 对个人生活长期有价值的一次性物品购置。

---

# 26. EXCEPTIONAL

少见且不希望污染正常生活成本的特殊事件：

```text
意外维修
临时长途交通
特殊医疗
突发损失
```

---

# 29. Normalized Living Cost

```text

```

```text

+

```



# 36. Deposit 语义

例如：

```text
支付押金 ¥5960
```

意味着：

```text
现金减少 ¥5960
```

但：

```text
正常消费 ≠ ¥5960
```

因为理论上仍然拥有：

```text
押金返还请求权
```

所以：

> Deposit 不进入 Normalized Living Cost。

只有：

```text
FORFEITED
```

的部分才计入真正损失。

# 45. 估计方式


# 46. 数据不足

必须设最低数据要求。

例如：

```text

```

```text

```

```text

```

```text

```
