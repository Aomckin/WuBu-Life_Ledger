## 明确的数据语义

资金唯一事实源为 money_transactions。余额缓存可由全部事件的 delta_cents 重算；每条流水保存 before/after/delta，校验 after = before + delta。绝对 amount 为非负整数分，方向由类型与 delta 决定；只有初始零余额或无差异核对可产生零调整，零价购买也保留购买关联。

账户仅 CNY。信用卡是净余额，消费形成负债、还款通过转账增加余额；额度不计资金，也没有账单日、利息和分期。total_balance 包含真实账户净余额；available_balance 为启用的非信用卡账户余额之和。未指定账户不参与这两个总数。

所有无法确认付款账户的旧费用都进入未指定账户，保持原 ID、金额、时间、分类、商家、购买/维护链接。该账户余额累计反映旧支出，不表示真实钱包余额。用户创建真实账户时输入当前余额，其初始状态单独留下 INITIAL_BALANCE 事件，不伪造过去的付款账户。

默认账户保存在 money_settings。购买显式 account_id（允许精确账户名称）优先；旧 payment_method 若恰好对应已建账户名称也可覆盖默认账户，其余保留为原始支付说明。付款账户停用后不再接受新流水，停用默认账户前需更换默认账户。

退款关联原 EXPENSE，累计退款不得超过原金额。发生时间范围内的净支出 = 支出 - 退款，因此退款跨月时退款月份可能为负净支出。转账和调整不计收入支出。资金退款与实际退货分开：return_items 只在明确退回商品时提供，数量受原购买和剩余库存约束，耐用品退回进入 RETIRED，失败全部回滚。

购买改单/撤销将原支出标记为已纠正，新增反向 ADJUSTMENT 补偿原账户；改单再写新 EXPENSE。统计排除已纠正条目，完整资金流水保留原条目与补偿事件。已退款购买禁止改单或撤销，避免重写退款依据。

耐用品数据库状态 ACTIVE/STORED/LOST/SOLD/RETIRED；STORED 仍拥有数量 1，LOST/SOLD/RETIRED 数量为 0，变化留下 InventoryEvent。SOLD/RETIRED 为终态。旧数据库 ARCHIVED/DISCARDED 映射 RETIRED；兼容 PATCH 新收到 ARCHIVED 作为 STORED、DISCARDED 作为 RETIRED。购买、启用、收纳、移动、丢失、找到、售出、退休都有独立事件，旧库存写入口不能绕过生命周期。

商品实际购入支出按 PurchaseItem 的小计比例分摊整笔实付；小计均为零时按行均分。维护费用和退款纳入商品统计。total_cost 是购入 + 维护，net_cost 再扣退款；售出收入单独保留，不改写原购入价格。

## Agent 与接口

新增高层工具包括 create_account、set_default_payment_account、record_income、record_expense、transfer_money、record_refund、adjust_balance、reconcile_account、add_maintenance、sell_item、retire_item、move_item、set_durable_status，以及账户/余额/汇总/流水/耐用品/成本查询。

record_purchase 仍用短参数，新增 account_id、item_type、location；不需要先拆成库存及账户 CRUD。所有关键写入工具要求稳定幂等键。工具返回余额前后变化或物品状态；不在网络失败后偷偷自动重试。

全部 REST 已同步 internal/web/static/openapi.json，并运行 scripts/sync-tool-schema.py。scripts/update-v02-openapi.py 可重复生成本版本扩展，保留原 Stockroom 契约。

## CSV 范围

支持 UTF-8 CSV；Generic 必需 occurred_at/type/amount，可带 merchant/category/external_id/note。支付宝/微信按中文表头读取，兼容导出表头前的说明文字、空白和货币符号。非 RFC3339 的支付导出时间按上海时区解释。

导入先预览再提交，每批最多 500 条，整个批次同事务。优先订单号，缺少时按账户、类型、时间、金额、商家生成稳定指纹；重复数据只跳过，不产生额外余额变化。预览不修改账目。

非收支行不能猜成内部转账；需在 Generic CSV 明确 TRANSFER、from_account、to_account。退款需 related_transaction_id，不能仅凭“退款”字样猜原消费。显示已退款的原支付行需拆成明确的支出和关联退款；不从含糊导出制造错误账目。未完成支付行会忽略并在预览计数。没有自动银行连接，也不将流水强行转成商品库存。
