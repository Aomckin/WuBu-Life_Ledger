# 微信 CSV 导入修复（2026-11-01）

> 历史记录，描述 v0.3 的旧导入流程，不作为 v0.4 使用说明或验收基准。新版 `/weekly-sync` 直接读取微信原生 XLSX / CSV、支付宝原生 CSV 和指定银行模板，无需另存 Excel 或制作 Generic CSV。当前实现与验收见 [V0.4_DELIVERY.md](V0.4_DELIVERY.md)。下文保留当时的结果与限制。

## 修复与使用

- 文件上传先严格解码 UTF-8，失败后尝试 GB18030；识别微信表头后自动选择微信适配器。乱码不作为正常文本导入。
- 兼容 Excel 导出的斜杠日期（含分钟格式）和合法千分位金额；非法分组金额仍拒绝。旧 CSV 已丢失的秒或字符不会靠猜测恢复。
- 微信退款 / 已退款 / 对方已退还，以及不计收支的内部划转，不再导致整批失败；这些行不入账，预览和提交回执通过 skipped_rows 返回实际文件行号与原因。跨行引号字段按 CSV 实际行号定位。
- 本次只是明确行的导入，不代表整份账单已完成对账。退款需用 Generic CSV 的原支出 ID 关联；内部划转需明确双方账户。不会按金额、对方名称或相邻位置猜退款关系。
- Generic CSV 无效退款仍整体回滚；原有事务、稳定键和订单号去重继续生效。导入到用户明确选择的账户，不自动猜支付方式对应哪个现实账户。
- API 新增可选响应字段 skipped_rows，不改变请求字段；OpenAPI 与 sync-tool-schema.py 已同步。
