# 物簿 v0.1.1 验收记录

按《物簿 v0.1.1 Dogfooding 补丁任务书》完成 P0、P1，并实现 P2 中的购买预检查和常见容量/重量规格等价。购买改单、删除与单位词条作为同批独立功能交付。

## 单次购买

朝汐高层工具 `record_purchase` 只需商品明细和稳定幂等键；商家、实际付款、付款方式、备注选填：

```json
{
  "items": [{"name":"无糖可乐","spec":"2L","quantity":1,"unit":"瓶","price":5.5}],
  "idempotency_key":"purchase-20261006-001"
}
```

后端在一个事务中解析或创建 Item，写购买、明细、费用、库存和库存事件。返回 purchase_id、expense_amount、每行 quantity_added / inventory_after、validation_status 和 warnings，不需要再次查询确认。单商品只填 total 时推导单价；省略 total 按明细合计；金额都未知时默认 0，调用方应提供已知实际付款。

模型分别存储基础 name、spec、package_size、package_unit；兼容字段 unit 表示 inventory_unit。2L 表示包装规格，1 瓶才是库存数量。旧组合名称仅在接口边界和一次性迁移中拆分；前端合并名称与规格用于展示。

## 商品解析与反馈

- 统一 ItemResolver 用于购买、按名称查询、消费、纠正、开封、用完、弃置和库存收件箱；列表搜索展示候选而不选择一个。
- 名称/规格精确匹配 → 别名 → 归一化精确匹配 → 唯一高置信候选；基础空白、全角、大小写、数字和单位格式归一化。2L 与 2000ml、1kg 与 1000g 规格等价，库存单位不会据此换算。
- 只有购买允许创建无合理候选的新物品。其他事件返回 ITEM_NOT_FOUND；多候选返回 ITEM_AMBIGUOUS，附 id / name / spec / unit / current_quantity 与 suggested_action。
- 金额差异超过一分钱返回 PURCHASE_AMOUNT_INCONSISTENT；包装容量疑似被当成数量时返回 SPEC_QUANTITY_CONFLICT。警告不猜测或改写现实数据，前端及工具结果均展示。非法金额、数量或规格返回 ERROR，全部回滚。
- 来源支持 manual / agent / import / system，保留旧 receipt 兼容；朝汐工具自动写 agent。
- 关键事件支持稳定 Idempotency-Key。重放原提交结果，变更参数返回 409；失败不占用键。旧 DTO 的幂等指纹在新增可选规格字段后保持兼容。
- 耐用品购买也留下 PURCHASE 库存事件；数量变化、开封、改单和取消均可追溯。

## 预检查与接口

`validate_purchase` 不需要幂等键，仅在读取事务中解析和验证，不生成物品、购买、费用、库存事件或幂等记录。返回预计库存及警告；正式购买仍重新解析并提交。多个相同商品行的预计库存会合计。

新增 REST：

| 操作 | 接口 |
|---|---|
| 简化购买 | POST /api/v1/purchases/record |
| 简化预检查 | POST /api/v1/purchases/validate |
| 完整 DTO 预检查 | POST /api/v1/purchases?dry_run=true |
| 按名称事件 | POST /api/v1/items/consume、adjust、open、finish、discard |
| 规格查询 | GET /api/v1/items/resolve?name=无糖可乐&spec=2L |
| 改单 / 删除 | PUT / DELETE /api/v1/purchases/{id} |

OpenAPI 与高级工具请求契约已同步。高层工具参数独立于完整 REST DTO，没有 operation / payload 嵌套；高级 `wubu` 继续供耐用品、维护和记录修正使用。
