# 物簿 v0.2.1 交付记录

开发日期：2026-10-10。按《物簿 v0.2.1 开发任务书｜Account Classes》完成 P0 和 Phase A–H。v0.2 与购买行退款按钮调整已提交为 `6dca89b`。保留 Stockroom 结构及许可证；朝汐源码、配置、环境、缓存与数据始终只读。

## 完成的场景

微信零钱 500，茶颜会员 0。一次 top_up_account 实付 100、到账 110，原子产生：微信 TRANSFER_OUT 100，会员 TRANSFER_IN 100，会员 BONUS 10。结果微信 400、会员 110，收入与消费都不增加。会员购买 20 后余额 90、消费增加 20。首页与 get_balance 分别展示自由资金和受限消费储值。

无赠送充值只产生两条转账。少于实付的到账仍允许，差额记 ADJUSTMENT，返回 TOP_UP_VALUE_LOSS；不算普通支出。独立 record_bonus 仅允许进入 CONSUMPTION。

## 账户、统计与兼容规则

- account_class 为 STORAGE / CONSUMPTION，独立于 type；type 新增 MERCHANT_BALANCE。消费账户可绑定 merchant，校园卡等可不绑定。
- 创建账户未给 class 时默认 STORAGE。编辑当前分类不会修改 MoneyTransaction 历史；所有分类余额按当前分类解释，不重建历史账户类别。
- liquid_balance：启用的 STORAGE 真实账户余额；consumption_balance：启用的 CONSUMPTION 真实账户余额。二者均沿用信用卡排除规则，排除未指定账户。total_value 是二者相加。
- available_balance 是 liquid_balance 的兼容别名；total_balance 保留 v0.2 的所有真实账户净余额语义，包含信用卡和停用账户，不能当作自由可用资金。
- 账户统计返回实际充值本金、累计 BONUS、累计消费、退款、净消费、当前余额和 bonus_ratio。无充值时比例为 0。充值本金只统计高层充值事件，普通转账不混算。
- 绑定商家自动补全遗漏的购买商家并保存。明显冲突返回 409 / ACCOUNT_MERCHANT_MISMATCH，提供纠正商家或选择匹配账户的建议；预览、实际购买和改单一致，不静默扣款。
- 退款默认回原支付账户，也可显式指定其他账户。累计消费退款按原支出归属统计，即使退到存储账户也正确冲减原消费账户的净消费。
- 停用有正余额的消费账户返回 ACCOUNT_HAS_REMAINING_BALANCE，页面显示提示，记录与余额仍保留。默认支付账户停用前仍须先更换默认账户。
- 信用卡净余额、额度、退款、库存事件和既有导入去重规则沿用 v0.2。

## API、工具与页面

新增 `POST /api/v1/money/top-ups`、`POST /api/v1/money/bonuses`、`GET /api/v1/accounts/{id}/statistics`。账户创建、编辑及列表查询扩展 account_class / merchant，列表可按 active 筛选；余额与首页接口增加分类汇总。

高层工具新增 top_up_account、record_bonus、update_account、get_account_statistics；create_account / get_accounts / get_balance 同步扩展。全部写工具要求稳定 idempotency_key，失败不占键，不自动重试不确定写入。新能力也可由兼容 wubu 工具调用。OpenAPI 已更新到 0.2.1，已运行 scripts/sync-tool-schema.py 同步内嵌工具 schema。

首页两个主要资金数字分别是自由可用资金、消费储值，下方按存储账户 / 消费账户分组。账户页可创建、编辑分类和商家、充值及查看累计使用与最近 100 条流水。充值转出 / 到账与赠送均有独立中文标签。购买记录仍使用“明细、改单、退款、删除”操作组。

## 迁移与升级

schema 10→11 是事务化表迁移，旧账户全部赋 STORAGE，不猜校园卡或会员余额性质。资金流水行、rowid 排序、before / after / delta、余额、购买、库存、耐用品、维护、导入外部编号、退款关联和幂等记录保留。expenses 保持只读兼容视图，资金事实源仍只有 money_transactions。

启动时自动迁移。升级前先停止旧服务并备份现有正式数据库；使用现有 scripts/start.ps1（不带 NoBuild）重新构建启动，再刷新页面。迁移后可在账户编辑中把校园卡或会员储值改为 CONSUMPTION。

本次没有对正式 data/wubu.db 执行迁移、写入或验证，也未重启用户的正式服务。已验证的迁移路径使用系统临时数据库。
