# v0.4 审计

## 2026-11-03 · 新版 P0 / P1 收口

唯一基准为 [Weekly Reconciliation & Semantic Backfill](<物簿 v0.4 开发任务书｜Weekly Reconciliation & Semantic Backfill.md>)，包括用户确认的 double-entry-generator、微信 / 支付宝专用原生入口、保留银行模板。旧 Financial Inbox 任务书已标废止。

本轮 P0 / P1 必需项已实现并通过隔离验收，逐项 A–J 证据、实际命令及边界见 [V0.4_DELIVERY.md](V0.4_DELIVERY.md)。P2 保持后续范围，不列为本轮已交付能力。

| 原先发现的缺项 / 风险 | 当前结果 |
| --- | --- |
| 仅旧通用CSV入口、依赖未接 | 两个原生专用入口 + 14银行模板；固定v2.16.0源码，实际Provider / IR调用 |
| 手工午饭与龙记重复扣款 | 商家名不同的唯一跨源候选匹配；包含老无Raw手工记录回归 |
| 一条坏金额阻断整文件 | 坏行独立保留审核，有效行继续；整批事务中途失败仍全部回滚 |
| 无ImportBatch / 周汇总 | 原件BLOB、hash、逐行回执、重导提示、历史、按来源与账户核对已贯通 |
| 上游过滤退款 / 原始行 | 独立保留每条源记录；退款、关闭、划转、外币均明确状态 |
| 同价 / 单号误合并 | 无ID同秒两行独立，不同银行同单号隔离，多候选不猜、UI不预填第一项 |
| 银行只有日期、信用卡还款 | DAY精度不捏造时刻；检查点同日歧义审核；还款关联双向TRANSFER，不自动记收入 |
| 同文件换账户可再次扣款 | EvidenceKey不含账户映射，改账户重导冲突且保留原链接 |
| 旧库 / 回执丢失 | schema12 / 13升14、连续重启、旧key重放与原文件下载回归 |
| 上游reader遗留Windows句柄 | 固定源码本地补丁，临时目录实际为空的回归通过 |
| 汇总被500条历史页截断 | 汇总独立全scope读取，501批次测试通过 |
| 固定源码影响Docker缓存层 | 依赖下载前COPY本地replace源码；未宣称容器运行已验收 |

最终全套 Go / vet、Python / SDK、前端以及两套 v0.4 Headless Edge 流程通过；旧 v0.2 浏览器流程此前本轮通过。银行模板的25份原生样本与账本集成测试均为本地实跑，生产服务 / 数据和朝汐未操作。

## 历史审计快照

2026-11-02 的开工检查曾复现商家不同重复扣款、坏行阻断，且当时依赖 / 原生入口 / 批次尚未接入。上述缺项现已修复并回归；不能把历史开工状态当作当前状态。

2026-11-01 母体资金事实位于 money_transactions，已有 postMoney 事务、ledgerTx串行锁及请求哈希幂等，schema12。此前语义存于category、未知默认other，核对余额只有调整事件。v0.4 增量引入独立原始证据、Annotation、检查点与补偿，随后schema14增加原生文件批次；不反向伪造旧数据证据。

开工已有多处未提交源码 / 文档，始终保留，没有混合提交或推送。此前手机子项目及相关工具已按用户决定撤除，未清除历史资金数据。相邻朝汐整个项目只读，适配仅本仓库 tools/wubu_tool；资料库未越权写入。
